## 2026-10-03 · 扩展私有化与首次验收

### 做成了什么
- Fork `download-zhihu` → 项目内 `extension/`，改名「知乎分析采集器」`0.1.0`
- 导出 `*.bundle.json`（评论树 + 富字段）；MD 保留
- 样例验收：页面 **97** 条评论 ↔ bundle **97** 节点（县城中学那帖）

### 经验（按优先级）
1. **加载路径勿含中文**  
   从 `…\个人项目\…\知乎…\extension\dist` 加载解压扩展，常「点选择文件夹没反应」。  
   **固定用**：`E:\zhihu-analysis-collector-dist`（构建后复制过去再「重新加载」）。

2. **别混装多份**  
   解压加载 + 拖 CRX + 重复加载 → 扩展页出现多个同名 ID。  
   **只留 1 个带「重新加载」的解压版**；关掉商店版「知乎文章下载器」；一般不拖 CRX。

3. **导出对象必须是回答直链**  
   导问题页 → 评论常为 0。正确：`/question/…/answer/…`。

4. **完整性对照**  
   以页面「N 条评论」对 `bundle.stats.total_nodes`（或评论 MD 头）。  
   `paging.totals` 多为全部评论数，不是一级条数；勿拿一级条数去比 totals（误报已修）。

5. **改造入口**  
   改商店安装目录会被覆盖且难读；应改源码 → `npm run build` → 同步英文目录 → 重新加载。

### 已知小缺口（非阻塞）
- 回答 `voteup_count` / `comment_count` 有时为 `null`（正文赞数未吃满），后续补。

### 更新扩展的固定流程
```text
cd extension → npm run build
→ 复制 dist\* 到 E:\zhihu-analysis-collector-dist\
→ edge://extensions/ 点「重新加载」
→ 打开回答直链导出（评论 + JSON）
```

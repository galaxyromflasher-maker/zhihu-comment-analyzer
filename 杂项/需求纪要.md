# 知乎分析系统 · 需求纪要（第 1 步收束）

更新日期：2026-10-03

## A. 目标与场景

- **主对象（一期）**：单条回答 + 其评论区（含评中评）。
- **后续**：问题页、专栏文章也可提取（采集打通后迁移成本低）。
- **入口**：回答直链，例如  
  `https://www.zhihu.com/question/.../answer/...`
- **典型意图**：以答主回答为树根，看评论区对答主的评价与引申思考；理想有支持/反对/中立占比（难度高可后置）。
- **成功线（采集）**：页面上可见的有效文本评论抓全率 **≥90%**；折叠广告/已删除不计入分母。
- **样例（原目标帖）**：  
  https://www.zhihu.com/question/2078918941477545304/answer/2088362780688760951  
- **已验证样例（扩展导出）**：  
  `杂项/为什么国外现在都不播报稀土了？-臭打游戏的的回答/`（93 条评论，结构正确）

## B. 采集范围

- **结构**：回答为根 → 一级评论 → 评中评，保留父子关系；纯评论文本用于树状分析材料。
- **字段尽量全**：昵称、内容、时间、点赞、IP 属地、父评论/回复对象、用户标识等；图片/外链存 URL（可不下载图到分析主路径）。
- **完整性**：必须展开「查看全部 N 条回复」类分页；有缺口要标记，不装抓全。
- **批量**：一期多 URL 串行即可；单帖数百级评论为设计基线。

## C. 采集方式与约束

- **定稿**：β′ — 以「知乎文章下载器」为采集器 + 自建数据/分析管道。
- **登录**：使用日常已登录 Edge；仅个人学习研究，原始数据不外传，不绕付费墙。
- **扩展**：商店版路径仅作对照，**不直接改安装目录**。改造基于开源仓 fork：  
  https://github.com/chouheiwa/download-zhihu  
  本地安装参考：  
  `%LOCALAPPDATA%\Microsoft\Edge\User Data\Default\Extensions\hancngfbcenkhbcabdgfkkhccbgfllpf\3.1.0_0`
- **原理要点**：页内 `fetch-bridge` + `comment_v5/.../root_comment` API。
- **改造方向**：已开工 — `extension/` 私有化「知乎分析采集器」，导出 `*.bundle.json`（富字段评论树）；MD 保留。
- **加载**：构建后用 Edge 加载 `extension/dist/`，勿改商店安装目录；与商店版勿同时开。
- **兜底**：API 失败时 HTML/DOM 解析（WorkBuddy 思路）。

## D. 分析与报告

- **P0**：答主摘要；**议题树**（以答主回答为根，分支为评论引申）；对答主态度（支持/反对/中立+占比，估算）；争议点；高赞/典型原话。
- **P1**：情感正负；简单热度/时间分布。
- **模型**：默认 DeepSeek；复杂归纳可切千问 / GPT 中转。Key 本地配置，不进 Git。
- **报告**：`topic_tree.md`（含 Mermaid 图谱）+ `analysis.md`；需要时再出 Excel 表。中文、自用可读即可。
- **入口**：`python run.py path/to/xxx.bundle.json`

## E. 产品形态与技术

- **优先级**：① 改版扩展采集 → ② Python CLI 分析一键 → ③ 可选 Cursor Skill。
- **一期不做**：本地 Web、BettaFish 整仓、重多 Agent。
- **BettaFish**：只学报告结构。
- **栈**：Python；先 JSON/Markdown 落盘；Windows；不上 Docker。

## F. 分期

- **一期路径 C**：先用现成扩展 MD 跑通「解析 → JSON 树 → Markdown 报告」；紧随其后 fork 扩展加 JSON/富字段。
- **无硬 deadline**：方案对齐后再开工。
